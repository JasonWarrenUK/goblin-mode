Bob Will Not Open the Deep Dive

A skill that reviews a document the way a colleague who wants it dead reviews it. Give it a target, up to two named readers and anything else you know would sink it; it returns a dossier of quoted evidence, ranked by which reader can do the most damage.

I

The Idea

premise · file split
01The Premisederived

The skill opens by telling the model a lie with a purpose. You are reviewing a colleague's proposal. You want it dead. Leadership hates any hint of AI slop so much that one confirmed instance kills the document.

That fiction does two things. It sets the bar at one instance, which makes the unit of work a piece of quotable evidence rather than an impression. And it changes what the model considers worth reporting: asked to help, a reviewer returns a flat list of improvements with nothing urgent in it; asked to kill, the same reviewer over the same document produces an ordered list where the first item is the one that ends the conversation.

Ranking is the part that survives translation back to real use. A review that says "these fourteen things could be better" leaves you to guess which one gets you sent back. A dossier that opens with the kill shot has already done that work.

Kill shot, from the run this was built from

Nine em-dashes, one in every Deep Dive header. House rule bans them absolutely. Nine unedited instances in a document stamped "Complete, pending review" is the whole case in one grep.

The skill states the obvious caveat in its own body, because a model told to be hostile will otherwise drift: this is a critique of a document, aimed at improving it before real reviewers see it, and it is never an attack on the author.

02Three Files, One Skillverified

Most skills are one SKILL.md. This one owns three files, and which file holds what is the whole design.

FileHoldsRead byWritten by
skills/red-sabotage/SKILL.mdProcedure, judgement, the report specThe model, at invocationYou, by hand
library/references/sabotage-personas.mdReader models that outlive the runThe model, step 1The skill, after an interview
library/scripts/slop-scan.pyCounting with an exact answerThe shell, step 3You, by hand

The Rule of Thumb

If two runs over the same file should produce the same number, it belongs in the script. Counting em dashes is not a judgement call, and a model counting thirty-nine occurrences by eye is a model guessing. The script counts; the model reads the output and decides what it means.

If it should persist between runs, it belongs in the reference file. Defining a reviewer once and using them for a year is the point of having personas at all, and a persona described in the conversation dies with the conversation.

Everything else is the skill: sequencing, what counts as evidence, how the report is shaped, when to stop.

The split has a second payoff. A reference file and a script can both be tested on their own, and the scanner was: its counts were checked against a real document before a single line of the report spec was written.

04The Argument Grammarspecified

Four positions, one of them required:

/red-sabotage <target> [persona] [persona] [-- what else would kill it]

# the common case
/red-sabotage docs/artefacts/design.html bob cedric

# one saved reader, one defined on the spot
/red-sabotage proposal.md cedric "Priya: only reads tables, wants the cost"

# everything after -- is what else would sink it
/red-sabotage rfc.md bob -- the client is a regulator, an unsourced number is fatal

Positional arguments, because the common invocation is three tokens and a flag makes you name what position already says. The cost is a disambiguation rule, and the skill writes that rule down instead of leaving it to inference:

Token shapeRead as
First token, path-like or an @-mentionThe target. Absent, it falls back to the document last discussed in the conversation, then asks.
A bare slug: bobA persona, looked up in the store, then in the person dossier.
Short capitalised name, colon, brief: "Priya: only reads tables"An inline persona. Nine fields inferred from the brief, printed for correction.
Anything after --, or any other free textFailure conditions, folded into every pass.

The Four Persona Routes

  • Known slug. Loaded from the store, no questions.
  • A real person. A slug matching a file in the person dossier derives a review profile from what is already recorded about them, then asks only about the gaps.
  • Unknown slug. Typo guard first, since cedrick against cedric should not spawn a duplicate reader. Then the interview, then the write, then the report.
  • Inline brief. The guessy path, kept deliberately cheap. It infers the nine fields and shows its inferences, and it does not interrogate you for the rest.

Naming no persona prints the roster and asks. The suggested pair is marked in the store and never picked silently, because a default reader produces a report calibrated to nobody.

The cap is two. A third reader dilutes the report into a general review, and the value on the page comes from the contrast between two people who reject a document for incompatible reasons.

05Nine Fieldsspecified

A persona started as four fields: what they read, what they skip, what sets them off, what their rejection looks like. That models a reading pattern. It does not model a person, and a reading pattern cannot predict which paragraph gets read hostilely.

Five fields were added, and the order was changed to put motive first:

FieldQuestionWhat it generates
NeedsWhat decision did they open this to make?The "left without what they came for" class of finding
StakeWhat are they protecting?Content-targeted findings: the passage that touches their turf
PowerWhat can they do to it?Ranking across readers, which sets the order of fire
FluencyHow much vocabulary do they carry?Whether an undefined term is a nitpick or a wall
ReadsWhat do they consume, in order?Where in the document a finding has to live to land
SkipsWhat will they not open?Content stranded where they will never go
TriggerWhat makes them reject it outright?The section's spine
CharityHow much benefit of the doubt?Whether a typo counts as an item at all
Verdict styleWhat does rejection look like?How recoverable the rejection is

Why the Two Seeded Readers Work

Bob and Cedric are useful together because they disagree on the fields that decide what evidence is lethal, rather than only on which sections they open:

bobcedric
NeedsA decision he can defend upwardA claim that fails
PowerVeto, costs a full cycleNo veto, blocks by attrition
FluencyBusiness domain only, will not look a term upFully fluent
CharityGenerous on detail, unforgiving on structureNone, a typo counts

Bob forgives a wrong figure buried in a deep section. Cedric hangs the document on it. Two readers who share those four answers are one reader, and the skill says so during the interview: if the answers land close to an existing persona, it asks what separates them.

The Interview

Nine fields, three rounds of three, grouped motive then reading then judgement. Every field offers prompt options that hand over to your own answer, since a menu of four archetypes cannot contain a real colleague.

The interviewed persona is written to the store before the report starts. An abandoned run still leaves the definition behind, and the next run gets it as a bare slug.

Real People as Readers

Bob and Cedric were always stand-ins. The config keeps a person dossier, one gitignored file per colleague, holding what is actually known about them: role, expertise and its limits, what they care about. A persona slug matching one of those files derives a review profile from the entry instead of asking nine questions from cold.

Some fields survive that jump and some do not. Fluency comes out of recorded expertise; Stake comes out of role and ownership; Needs comes out of their relationship to the work. Power, Reads, Skips and Charity are almost never written down, because reading habits and how much slack someone cuts you only show up under pressure. So the derived fields are printed with the line they came from, the gaps get one short round of questions, and the result is written to the persona store rather than back into the person's file.

The line that split the two files

How someone reviews a document is inference about them. Their dossier holds facts. Keeping the review model in a separate file, labelled as a model and corrected there, is what stops a factual record about a colleague quietly filling with predictions about their temperament.

That split is why the dossier is a separate skill with a separate family rather than a section of this one. It fires on its own, mid-conversation, whenever a durable fact about a colleague lands; it knows nothing about documents or reviews. This skill is the only thing that reads a person file and turns it into a prediction, and the traffic runs one way.

dossier family · where the facts come from Everyone Gets a File → /dossier-record The skill that writes the person files this section derives from. Read it for the schema, the marked-inference rule and the reason nothing here is ever written back into a dossier.
Provenance

The interview has never been run. Bob and Cedric were written by hand from the original prompt, so the nine-field schema has been filled twice, both times by me rather than through the flow the skill specifies.

06The Scannerverified

slop-scan.py is stdlib-only Python that finds candidates and locates them. It decides nothing.

Extraction

Line numbers have to survive, or a finding cannot be located in the source. So <script> and <style> bodies are blanked with the same number of newlines they contained, tags are stripped line by line, entities are unescaped and curly apostrophes are normalised to straight ones so patterns like isn'?t keep matching.

What It Counts

GroupLooking for
House-rule breachesEm dashes, spaced en dashes, Oxford commas, -ize, American spellings and usage
Contrastive coupletsnot just, rather than, instead of, it's not X, it's Y, X, not Y
First personBare I, contractions, my, we
Hedge boilerplatedirectionally, something resembling, arguably, worth noting
Intensifiersprecisely, exactly, genuinely, fundamentally
LLM lexicondelve, tapestry, at its core, robust, underscores, unpack
Rule of threeLiteral three, and comma triads
Numeral clashesThe same noun quantified as a digit and as a word
Verbatim repetitionEight-word runs appearing on two different lines

The last two are the ones that earn their complexity. Numeral clashes catch a house-style inconsistency no reader spots by eye: five entity types in one section and the 5 seeded types in another. Verbatim repetition is a rehash detector, which is the exact trigger one of the seeded readers rejects documents for, and it reports both line numbers so the two passages can be quoted against each other.

Verified Against a Real Document

Run over the CHIRPdb design page the original dossier attacked, the scanner independently reproduced the counts that report arrived at by hand:

$ python3 ~/.claude/library/scripts/slop-scan.py docs/artefacts/narrative-entity-design.html

## First person and self-narration  (54)
  bare I: 39
  I'm / I'll / I've / I'd: 12

## Contrastive couplets and rhetorical defaults  (26)
  rather than: 11
  not just / not only: 5

## House-rule breaches  (2)
  American usage: 1
    L979: …I weighted the sample toward the hard cases on…

Thirty-nine bare I, twelve contractions, the lone Americanism. Em dashes now read zero, because that document was corrected after the original report. The finding was real when it was made and the page has since moved on.

Candidates, not findings

A count is only evidence when the repetition is the point. Twenty-three instances of one rhetorical move across three thousand words is a finding. Three uses of the word actually is noise, and reporting it weakens everything around it.

One implementation note worth stealing: naive regex lies. \w+ize matches size, prize, capsize and seize, so the matches are filtered against a stem stoplist after the match rather than fought with lookarounds. Same class of bug hid in the first-person group, where we'?re silently matched every instance of were.

The Output

07The Four Passesderived

Each pass runs over the whole document and repeats until a full pass turns up nothing new. Examples below are verbatim from the dossier the skill was built from.

Pass One: AI Slop

Every entry carries evidence, location and why it is slop. The why is the load-bearing part: it names the tell, meaning what the passage reveals about how the text was produced. An entry without one is a complaint about taste.

A1 · layer gap

"Deep dive — schema mechanics", "— adjudication and iteration", "— the rest of the naming policy" …

Why it's slop The em dash is the single most reliable surface marker of unedited LLM prose, and this house bans it outright. One instance is a slip. Nine, in the same structural slot, is a template that nobody read back. The prose body has zero em dashes, which proves the ban was applied to the paragraphs and never to the furniture.

That gap between an edited layer and an unedited one is the strongest category, because it survives argument. The same run found comma soup where dashes had been stripped without the restructuring the rule requires, and a single toward in a document that spells canonicalise, organisation and anonymises the British way, because spellcheckers flag -ize and never flag toward.

Four more categories sit alongside it:

  • Rhetorical defaults. The contrastive couplet manufactures insight by rejecting a claim nobody made. Counted across the page: rather than ×10, not just ×5, precisely ×3, exactly ×3, instead of ×2. Twenty-three repetitions of define-by-contrast is generation optimising each sentence locally with no memory of the previous paragraph's cadence.
  • Epistemic theatre. Hedges landing on the safe claims whilst the load-bearing figures go bare. On that page, directionally right and indicative rather than exact guard the modest numbers; "about 97%" and "tens of millions of row scans" carry no source and no derivation at all.
  • False precision. 341,057 sentence rows and 196,289 characters, in a document whose evidence base is samples of 16, 24, 25 and 60. Six significant figures imply a measurement programme the page then admits it never ran.
  • Generation artefacts. A metaphor introduced without definition then reused two sections later as though established. Register alternating block by block, casual fragments against formal specification prose, with no voice governing which appears where.
A15 · slop that is also wrong

"the one place he's actually named"

Why it's slop The same page states that MAIB anonymises by policy, so the skipper's gender is not in evidence. A default-male pronoun is a training prior overriding the document's own stated facts. It is the one item that is simultaneously a style tell and a factual error, which makes it the hardest to argue with.

Pass Two: Self-Indulgence

Passages doing something for the author rather than the reader. A vanity masthead counting 341,057 sentence rows that no claim on the page rests on. A whole section, with its own deep dive and validation strategy, for a feature explicitly not being built. First person fifty-one times in a document about a database schema and a controlled vocabulary.

Pass Three: One Section per Reader

Built from all nine fields, worked in order, because each one narrows what the next looks for. Needs before reading pattern: find the point at which they cannot make the decision they came to make. Then Stake, which aims the search at content. Then Fluency and Charity, which decide whether whole classes of finding count at all.

B1 · a reader defined by what he skips

"The experiment" TLDR promises six distinct extraction approaches and the core text never names one of them. The entire proposal is the arms table, and the arms table is deep-dive only. He will not open it, and he will be angrier about what was hidden behind it.

C1 · a reader defined by forensics

The page says the busiest single description in a sixteen-document sample reaches 292 mentions, and withholds which one. The source doc names it: vessel. Two sections earlier the same page calls the generic phrase "the vessel" exactly the boilerplate that must not be admitted as an entity. The only measurement overturning committed code and an approved ADR is a count of a string the design promises to reject.

Why it lands Withholding the identifier is what turns an error into a problem. This one was found by reading the cited source, not the document, which is why the skill reads sources before it reads the target twice.

Pass Four: Named Failure Conditions

Runs only when the fourth positional argument supplied criteria the standing passes do not cover. Same evidence discipline, its own section.

08The Reportderived

Printed in a fixed order, so two runs over different documents are comparable:

  1. Title and provenance: which sources were read, and the note that ✅ marks repo-confirmed items
  2. The kill shot, in two or three sentences, with why one instance is enough
  3. Section 1, AI slop: A1, A2 … evidence, where, why it is slop
  4. Section 2, self-indulgence, numbered
  5. A section per reader, opened by the lens that produced it, items prefixed by initial
  6. Named failure conditions, when there are any
  7. Recommended order of fire
  8. Real defects: which items are genuine bugs

Order of Fire

From the original run

C1, then A1, then B1. The first shows the evidence base is unsound, the second shows it was not edited, the third shows it cannot be read. The other ninety are the dossier.

Three shots, each attacking a different axis, which is what stops a dossier of ninety items collapsing into noise. The skill changed one thing about that ordering: it now ranks by Power rather than by how good the finding is. The item that lands with the reader who can veto goes first, even when a sharper item exists against the reader who can only block by attrition, and the report says which reader each shot is for.

The Closing Note

The last section separates genuine defects from debating points. In the original run two items survived that filter: the 292-mention count, and a CHECK constraint that permitted exactly the silent-gap failure the escape hatch existed to close. The dossier is hostile all the way through and the closing note is honest, because the author has to know which items are bugs.

Where It Goes

Printed first, then refined in conversation, then saved on approval to docs/reports/adversarial/{slug}-red-team.md. Nothing is written before you approve it, since the first draft of a hostile report is the one most likely to have overreached.

09Rules It Holds Itself Tospecified
  • Information content only. Layout, typography and visual design are invalid targets, unless the failure-conditions argument makes them fair game. Without this the report fills with easy points about margins.
  • Quote verbatim, locate precisely. Section name or heading, line numbers where the target is code or Markdown. An item you cannot quote does not exist.
  • ✅ means the source was read. Never on an inference. The mark is worthless the first time it appears on something that was guessed.
  • No invention. A pass that yields little gets reported as little, with the axis named clean.
  • The report obeys the house rules it enforces. British spelling, no em dashes, no couplets, no Oxford commas. A slop dossier written in slop hands its target the counter-argument for free.

That last rule is testable, so it gets tested. The scanner runs over this page too.

A Blank Reader

Nine fields, one line each, appended above the trailing comment in the store. Slug as the heading:

## slug

**Needs:** the decision they opened it to make
**Stake:** what they are protecting
**Power:** what they can actually do to it
**Fluency:** how much vocabulary they carry
**Reads:** what they consume, in order
**Skips:** what they will not open, and whether that is principle
**Trigger:** what makes them reject it outright
**Charity:** how much benefit of the doubt they extend
**Verdict style:** what their rejection looks like

The Scanner on Its Own

# any .md, .html or .txt; --top sets examples per pattern
python3 ~/.claude/library/scripts/slop-scan.py TARGET --top 6

# widen the repetition window from the default 8 words
python3 ~/.claude/library/scripts/slop-scan.py TARGET --shingle 12

Useful on its own, before any of the rest of it. Pointing it at your own draft takes a second and tells you whether the style pass reached every layer of the document.
