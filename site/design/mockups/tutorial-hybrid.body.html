Give It a Script and a Ledger

At level 1, tidy-imports was one file that asked Claude to sort a file's imports by hand. This level gives the sorting to a script, lets that one script run without a prompt and keeps a ledger of every file it touches.

---name: tidy-importsdescription: Sort the import statements at the top of a filearguments: [path]---Tidy the imports in $path.Sort the import statements at the top of the filealphabetically, one per line. Leave everything belowthe imports exactly as it was.

At level 1, Claude sorted the imports itself, and a model asked to reorder lines will now and then reflow one it was told to leave alone. A script does the same thing every time and costs no tokens, so the sorting moves into scripts/sort-imports.sh in the skill's folder.

The new script, whole:

tidy-imports/scripts/sort-imports.sh

#!/usr/bin/env bash# Sort the import lines at the top of a file, in place.set -euo pipefailfile="$1"# How many lines from the top start with "import "?count=$(awk '/^import /{n++; next} {exit} END{print n+0}' "$file")if [ "$count" -eq 0 ]; then	echo "no imports at the top of $file"	exit 0fi{ head -n "$count" "$file" | sort; tail -n +"$((count + 1))" "$file"; } > "$file.tmp"mv "$file.tmp" "$file"echo "sorted $count imports in $file"

Make the script executable once with chmod +x. Then replace the three sorting lines in SKILL.md with the script call 2.1a and tell Claude to keep its hands off the sorting 2.1b.

SKILL.md after step 2.1

.claude/skills/tidy-imports/SKILL.md

---name: tidy-importsdescription: Sort the import statements at the top of a filearguments: [path]---Tidy the imports in $path.Run the script on the file, by exactly this path:```bash.claude/skills/tidy-imports/scripts/sort-imports.sh "$path"```It sorts the import block in place. Do not reorder anylines yourself or edit the file after it runs. If thescript exits non-zero, report its message and stop.

  1. 2.1a The script call takes the place of the three lines that told Claude how to sort.

  2. 2.1b Hands off the sorting. Claude reorders nothing itself and leaves the file alone after the script runs; a non-zero exit ends the run with the script's message.

Running a script is a Bash call, and Claude asks before each one unless the skill approves it. allowed-tools 2.2a approves calls for as long as the skill runs; naming the script's full path, with :* for whatever arguments follow, approves that one script and no other command.

The rule matches the start of the command, so the script call from 2.1a uses exactly that path, with no bash or ./ in front.

A ledger lets a later run say what an earlier one touched. The script appends one line per file to .claude/tidy-imports.log, the path and how many imports it sorted, so writing the ledger needs no extra permission.

The script's two new lines:

tidy-imports/scripts/sort-imports.sh

...file="$1"ledger=".claude/tidy-imports.log"...mv "$file.tmp" "$file"printf '%s\t%s\n' "$file" "$count" >> "$ledger"echo "sorted $count imports in $file"

.claude/tidy-imports.log after two runs

src/app.ts	6src/routes/home.ts	3

SKILL.md tells Claude to read the ledger first 2.3a and to leave the writing to the script 2.3b.

The Real Thing

project-tag_version lives in this repository and tags a release after a merge to main. Its first marked line, disable-model-invocation R.a, is a move tidy-imports does not have yet. The other two are this level's moves: allowed-tools names a script by its path R.b and the body runs that script R.c for the part that must come out the same every time.

skills/project-tag_version/SKILL.md

---name: "Project: Tag Version"description: "Tag the release after a merge to main, computing the next semver tag with svu"...disable-model-invocation: trueallowed-tools: ["Bash(svu:*)", "Bash(git:*)", "Bash(~/.claude/library/scripts/safe-version-next.sh:*)"]...---# Tag the release with `svu`...```bashTAG="$("$HOME"/.claude/library/scripts/safe-version-next.sh)" && git tag "$TAG" && git push origin "$TAG"```...

  1. R.a disable-model-invocation stops Claude starting the skill on its own, so it runs only when a person types its slash command after a merge has landed, because a pushed tag is hard to take back.

  2. R.b allowed-tools names safe-version-next.sh by its full path, the move from 2.2a, beside svu and git for reading history and pushing one tag.

  3. R.c The body runs the script and tags whatever it prints, so Claude never works out the next version itself.

Try it: make the ledger line include the date

Change the script so each ledger line starts with the day it was written. Then change the ledger paragraph in SKILL.md so Claude says when a file was last tidied.

Show the answer

In sort-imports.sh, put the date in front of the path:

tidy-imports/scripts/sort-imports.sh

printf '%s\t%s\t%s\n' "$(date +%F)" "$file" "$count" >> "$ledger"

date +%F prints the date as 2026-11-19, which sorts in date order as plain text. In SKILL.md, the second ledger line becomes: already listed there, say on which date it was last tidied.
