3III.1

On the Establishment of a Plan Where None Exists

When a project has ideas but no written plan

There is a repository and a rough sense of what it should become. Nothing is written down.

How Human Suffer Before

  1. Human ask Claude for plan. Get LIST. Just list. In Markdown.
  2. Order of task written in WORDS. "After auth." Is not edge. Is gossip.
  3. Next month human type new task anywhere it fit. Nobody check. Nobody wire it both way.

With goblin-scout

  1. /goblin-scout:start-roadbook writes .claude/roadbook.json as the single source of truth, plus a waypoint list and a prose overview generated from it.
  2. /goblin-scout:plan-expedition asks questions until vague ideas become a batch of well-formed waypoints. It writes nothing until the batch is approved.
  3. /goblin-scout:add-waypoints adds the batch, or one waypoint later: it gives each an id and records every dependency on both waypoints it joins.
  4. A project still on .claude/roadmaps.json is moved to the roadbook on its first write; /goblin-scout:rebind-roadbook does it by hand.
Goblin Ruling (Is Final)

Human with eight waypoint say no need graph. Human wrong. Get more waypoint.

III.2

On the Proper Selection and Claiming of a Task

When choosing the next waypoint on a shared project

Thirty waypoints, two scouts. One of them started something on Friday.

How Human Suffer Before

  1. Human ask Claude what next. Claude THINK about it. Fresh every time. No pane.
  2. Claude pick task. Other human already pick same task Friday! Nobody know!
  3. Who own task? Whoever say so in chat. Chat is not record.

With goblin-scout

  1. /scout-waypoints opens a pane with no model turn: every unblocked waypoint, most useful first. Below them sit the trails in progress, with scouts and start dates.
  2. A digit picks a row. c starts a trail and asks who is on it; a assigns a scout without starting. g regroups by scout, milestone or tier; s sets which group leads.
  3. Prefer to be told? /goblin-scout:suggest-waypoint recommends one waypoint; /goblin-scout:survey-waypoints lays them all out in tables.
  4. Create a branch without starting a trail and Claude asks one question: which ready waypoint is this, and which scout is on it? /goblin-scout:start-trail does the same by hand, and drops a trail that is abandoned.
  5. /goblin-scout:assign-scouts hands out waypoints across the whole team in one interview.
Goblin Ruling (Is Final)

Human who work alone say nobody need see trail. Goblin need see trail. Can switch question off per branch. Goblin not recommend.

III.3

On the Reconciliation of the Plan With Completed Work

After a pull request merges

The search waypoint merged an hour ago. Two others were waiting on it.

How Human Suffer Before

  1. Human tick own box with own hand. No graph. No skill. Is how accident happen.
  2. Two task still say BLOCKED. They are free! Nobody tell them. They wait forever.
  3. Three week later file say one thing, code say other. Nobody know what is done.

With goblin-scout

  1. The landing skill stamps an end date on the waypoints the pull request finished.
  2. /goblin-scout:tend-roadbook recomputes every status from the graph. The two waiting waypoints become ready and appear in the pane.
  3. /goblin-scout:tend-roadbook reconcile goes further and reads the codebase to find work that is done but unmarked.
  4. If the roadbook has drifted, the next session opens with a one-line nudge naming the fix.
Goblin Ruling (Is Final)

Human who like ticking box will lose tick at next recompute. Good. Box belong to graph now.

III.4

On the Exhibition of the Plan to Interested Parties

When someone outside the terminal asks for progress

Somebody who does not live in the terminal wants to see progress.

How Human Suffer Before

  1. Human send Markdown file. Or ask Claude for summary. No dashboard. Nothing to click.
  2. Summary come out different every day. Same plan! Two story! Which one true?

With goblin-scout

  1. /goblin-scout:unroll-chart renders the chart, an interactive HTML page, from the roadbook. A script does it, with no model, so the same roadbook always gives the same chart.
  2. /goblin-scout:configure-roadbook artefact <path> moves where the chart is written, a docs site folder for instance.
  3. The command line prints the dependency graph as a Mermaid diagram and gives plain statistics.
  4. Inside the terminal, the pane shows each milestone's progress by release tier.
Goblin Ruling (Is Final)

Human with nobody to show still need chart. Human can look at it alone. Is nice chart.

III.5

On the Periodic Review of the Plan's Fitness

When a roadbook has gone stale or a milestone has dragged

The roadbook is three months old. Some waypoints seem blocked for no good reason.

How Human Suffer Before

  1. Human ask Claude to review plan. Claude read file and give ADVICE. General advice. No lens.
  2. Is this edge real, or left from old idea? Human must guess from words. No audit.

With goblin-scout

  1. /goblin-scout:review-roadbook runs an interview through two lenses. Health covers stale waypoints, priorities and whether each milestone still means what it meant.
  2. The dependency lens audits each edge in the graph: does this waypoint truly need that one first?
  3. Nothing changes until the proposed edits are approved. A validate command checks the graph's integrity at any time.
Goblin Ruling (Is Final)

Review ask human many question. Human must think. Thinking good for human.

How to Use It

Install and first run

Add the marketplace once, then install the mod.

claude plugin marketplace add JasonWarrenUK/goblin-mode claude plugin install goblin-scout@goblin-mode

It needs python3 3.8 or later on your PATH. The /scout-waypoints pane needs Claude Code 2.1.287 or later; the skills work on any version. In a project with no roadbook, run /goblin-scout:start-roadbook, then /scout-waypoints to see what is ready.

Configure it

goblin-scout takes no options in Claude Code's plugin settings. Its one setting lives in the roadbook: where the chart is written.

SettingSet withDefault
Where the chart is written, per phase/goblin-scout:configure-roadbook artefact <path>beside the roadbook
Commands and skills

Generated from each skill's own file at build.

TypeWhat it does

/goblin-scout:survey-waypointsEvery ready waypoint, one table per milestone, topic or scout
/goblin-scout:tend-roadbookRecompute statuses after work lands; add reconcile to check the code
/goblin-scout:review-roadbookReview health and the dependency graph
/goblin-scout:unroll-chartRender the chart
/goblin-scout:configure-roadbookSet where the chart is written
/goblin-scout:rebind-roadbookMove an old roadmap file to the roadbook
Turn it off or remove it

To stop the branch question on one branch: git config branch.<name>.roadmapClaim none (today's key; the rename may change it). To remove the mod: claude plugin uninstall goblin-scout@goblin-mode. Your roadbook stays in .claude/roadbook.json; it is plain JSON and nothing else reads it.
